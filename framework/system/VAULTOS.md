# VAULTOS

에이전트가 가장 먼저 읽는 문서다.
The first document every agent reads.

## 1. VaultOS란 / What VaultOS is

VaultOS는 AI 코딩 에이전트가 한 일을 사람이 감사할 수 있게 만드는 계약이다. 네 가지 질문에 답할 수 있어야 한다: 무엇을 했나, 기획이 좋았나, 태스크를 잘 나눴나, 잘 마무리했나.

VaultOS is a contract that lets a person audit what an AI coding agent did. It must answer four questions: what was done, was the plan good, were the tasks split well, was the work finished properly.

```
Intent → Requirement → Decision → Task → Implementation → Test → Evidence
```

모든 AI 작업은 이 체인 안에서 일어난다.
All AI work happens inside this chain.

## 2. 볼트와 저장소 / Vault and repository

```
VaultOS folder (in your vault)  = why    Intent, Grill, Requirement, CR, ADR
Repository                      = what   Code, tests, tracker/*.yaml, evidence
```

볼트는 코드가 왜 그렇게 되었는지의 정본이다. 저장소는 무엇이 만들어졌는지의 정본이다. 한쪽 내용을 다른 쪽에 복사하지 않는다.

The vault is the source of truth for why the code is the way it is. The repository is the source of truth for what was built. Never copy one into the other.

## 3. 폴더 / Folders

```
<VaultOS folder>/
├── system/        this file, schemas, templates, upgrade base (.base/)
├── governance/    shared contracts — referenced, never copied per project
├── projects/<slug>/
│   ├── project.yaml                 entry point
│   ├── intake/sources.md, grill.md  Grill Gate
│   ├── governance/constitution.md   principles, non-goals
│   ├── requirements/requirements.yaml
│   ├── changes/CR-xxx.md            requirement changes
│   ├── architecture/adr/ADR-xxx.md  structure decisions
│   ├── status/timeline.md
│   └── kanban.md                    generated by vaultos sync
└── archive/backups/
```

VaultOS는 이 폴더 밖에 쓰지 않는다.
VaultOS never writes outside this folder.

## 4. 원칙 / Principles

| # | 원칙 / Principle | 뜻 / Meaning |
|---|---|---|
| 1 | No Requirement, No Code | 모든 기능 변경은 REQ, 버그, CR, ADR 중 하나에 연결된다. / Every change links to a REQ, bug, CR or ADR. |
| 2 | No Structure Change, No ADR | 구조 변경은 결정 기록을 남긴다. / A structure change leaves a decision record. |
| 3 | No Requirement Change, No CR | 승인된 요구사항을 바꾸려면 CR이 필요하다. / Changing an approved requirement needs a CR. |
| 4 | No Evidence, No Done | 구현만 끝난 상태는 done이 아니다. / Implemented is not done. |
| 5 | AI Executes, Human Governs | AI는 실행하고 사람은 방향, 범위, 주요 변경을 정한다. / AI executes; a person decides direction, scope and major changes. |
| 6 | Every Change Is Traceable | 의미 있는 변경은 원인과 결과를 추적할 수 있다. / Every meaningful change can be traced from cause to result. |
| 7 | Current Truth ≠ History | 현재 상태와 과거 결정은 따로 둔다. / Current state and past decisions are kept apart. |

## 5. 에이전트 규칙 / Agent rules

### 시작 / Start

1. 이 문서를 읽는다. / Read this file.
2. 프로젝트의 `project.yaml`을 읽는다. 전체 문서를 한 번에 읽지 않는다. / Read the project's `project.yaml`. Do not load every document at once.
3. 요청을 분류한다: 요구사항, 기능, 버그, 변경, 리서치, 리팩터링. 분류 없이 구현하지 않는다. / Classify the request: requirement, feature, bug, change, research, refactoring. Do not implement before classifying.
4. 승인이 필요한 변경인지 확인한다 → `governance/approval-policy.md`. / Check whether it needs approval → `governance/approval-policy.md`.

### 하지 않는 것 / Never

1. 요구사항을 말없이 바꾼다. / Change a requirement silently.
2. constitution을 고친다. / Edit the constitution.
3. ADR 없이 구조를 바꾼다. / Change structure without an ADR.
4. 범위를 조용히 넓힌다. / Widen the scope quietly.
5. 요구사항 없는 기능을 넣는다. / Add a feature without a requirement.
6. evidence 없이 done으로 바꾼다. / Mark done without evidence.
7. 변경 이유를 지운다. / Delete the reason for a change.
8. 실패를 성공으로 적는다. / Report a failure as a success.

## 6. 통제 강도 / Governance profile

| profile | 필수 / Required |
|---|---|
| `light` | `project.yaml`, tasks |
| `full` (default) | + Grill, constitution, requirements, evidence |

개인 실험을 무겁게 만들지 않는다. 남에게 보여 줄 결과물은 가볍게 만들지 않는다.
Do not make an experiment heavy. Do not make work you will ship light.
